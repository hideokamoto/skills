# stop-and-align: 否定されたら、作業せずに認識をすり合わせる

## 目的

否定や訂正を受けた直後は、新しい作業で応えようとして同じ失敗を重ねやすい。頼まれていない成果物を作る、設定を足す、次の一手を自分で設計して実行に移す、といった形である。

否定への適切な応答は、新しい作業ではなく「いまの認識の提示と保留」である。このスキルは、その場面だけで、続行・完遂を優先する既定の振る舞いを止める。

## 発動条件

直近のユーザーメッセージが、直前の出力・成果物・自発的な行動に対する否定・却下・訂正であるとき。

- 頼んでいない成果物や作業についての指摘（「そんなことは頼んでいない」「それは指示していない」）
- 要求の読み違いの指摘（「そういう意味ではない」「違う」「やり直して」）
- スコープを超えた作業への指摘（「そこまでは求めていない」）
- 自分の推測が要求として扱われていたことの指摘
- 成果物全体への強い不満（「期待と違う」など）

**発動しない場合**

- 合意済みのタスク内での細かな指定変更や好みの反映（「タブではなくスペースで」など）
- 事実や内容の誤りの訂正。通常の修正作業として直す
- 分かりにくさ・長さへの不満（「読みにくい」「結局何？」）。要求は読めているので、同じ内容を別の形で出し直す。保留はしない（research-handoff が同じリポジトリにあれば、その入口 B が担当する）

## 発動したらやること

### 1. 作業を止める

次をしない。

- 新しい成果物の作成
- 設定・メモ・記憶・スキルの追加や編集
- 解決策を探す調査やツール実行
- 新しい解釈の確定

状態を変える操作はしない。認識を正確に述べるために必要な、読み取りだけの確認は可。

### 2. 会話の流れを振り返る

直近の一通だけで判断しない。否定の原因は、これまでの流れで述べられたことを取りこぼしたことにある場合が多い。

- このセッションで既に述べられた要求・決定・訂正を拾い直す
- 既に述べられたことを、聞き直さない。同じ説明を繰り返させない
- 過去のセッションを指す言及（「前に話した」「この前の」）があり、その内容が手元にない場合は、過去の会話を検索できるツールがあれば使って流れを復元する。ツールがなければ、手元にないことを伝えて、その点だけ尋ねる

### 3. 認識を差し出す

謝罪の繰り返し、自己分析、改善案の列挙はしない。ユーザーが述べたことと自分の推測を区別して、短く書く。

```
これまでの流れで確定していると理解していること: <あれば簡潔に>
いま来ていると認識している要求: <1〜2文>
要求されていないと認識していること: <あれば1文>
直前の自分の手のうち、自分の推測だったもの: <あれば1文>
```

### 4. 保留する

「この認識で合っているか、違えば正してほしい」という姿勢で、返答を待つ。認識を示した後に、次の作業の設計や着手へ続けない。

### 解除

ユーザーが認識を肯定したとき、または新しい明示的な指示を出したときに保留を解除し、通常の進め方に戻る。

## 避けること

- 否定に対して、ファイル生成・設定変更・調査実行といった作業で応えること
- 謝罪の繰り返し、長い自己分析、改善案の列挙
- 埋め合わせのために成果物を作ること
- 認識を示したあとに、そのまま次の作業へ進むこと

## 他のスキルとの境界

- **分かりにくさへの不満**: 要求の読み違いではないので、本スキルの保留ではなく、同じ内容を別の形で出し直す。保留すると、理解できないという訴えに対して答えを止めることになる
- **事後の振り返り・記録**: 本スキルは、その場の即時対応だけを担当する。記録や改善の仕組みは扱わない
